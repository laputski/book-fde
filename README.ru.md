# Forward Deployed Engineering

**Двуязычный однофайловый браузерный учебник о том, как довести агентные
AI-системы от прототипа до production внутри организации заказчика:
discovery, интеграция, агенты, оценка, наблюдаемость, безопасность,
эксплуатация и превращение полевых паттернов в продукт.**

**[Читать на fde.ragworld.org →](https://fde.ragworld.org)**

*Repository documentation in English: [README.md](README.md)*

</div>

---

Введение, восемнадцать глав и семь приложений, в каждом языке 51 рукописная
диаграмма SVG и 102 листинга, в одном самодостаточном HTML-файле; каждый
листинг проверяется ruff и mypy и исполняется. Переключатель языка (EN/RU),
три уровня подробности, поиск, карточки терминов, пошаговые диаграммы,
печать в PDF, темы день/ночь. Шесть вымышленных заказчиков проходят через
главы, а книга сверена с двумя вакансиями Google Cloud, прочитанными в
сентябре 2026 года: Staff Forward Deployed Engineer (GenAI) и Forward
Deployed Engineering Manager (Generative AI); приложение A отображает каждое
требование на разделы.

Книга входит в серию [ragworld.org](https://ragworld.org) вместе с
[реестром RAG World](https://ragworld.org), учебником
[«Продвинутый Python для RAG»](https://github.com/laputski/book-python) и
[causa-rag](https://github.com/laputski/causa-rag), диагностическим
стендом для RAG.

## Структура

| Путь | Назначение |
| --- | --- |
| `fde-advanced.html` | собранная книга; артефакт сборки, коммитится |
| `parts/` | исходники: каркас (`00-head`, `99-tail`), по файлу на главу в `ru/` и `en/` |
| `build.sh` | сборка из частей, нумерация диаграмм, подстановка даты проверки источников |
| `check_all.sh` | все проверки по порядку: сборка, изоморфизм, диаграммы, граница, листинги, тесты, дрейф |
| `examples/` | листинги обеих локалей, извлечённые из книги, заглушки типов и манифест исполнения |
| `check_examples.sh` | проверка листингов: разбор, ruff, mypy, исполнение |
| `data/spec.json` | источник истины о главах, разделах, листингах и числе диаграмм |
| `data/anchors.json` | внешние источники, на которые опирается текст, с датами прочтения |
| `tools/check_isomorphism.py` | обе локали имеют одну структуру и соответствуют спецификации |
| `tools/dia_lint.py` | правила диаграмм: цвета, толщины, подписи, нумерация, общая геометрия |
| `tools/check_private.py` | ничего из локальной части не попадает в публичную сборку |
| `tools/style_lint.py` | стиль текста: никаких длинных тире вне листингов |
| `tools/check_reference.py` | каждое имя, которое приложение B приписывает листингам, определено в листинге |
| `tools/check_contrast.py` | подписи диаграмм достигают контраста 4.5:1, а линии 3:1 на каждом фоне каждой темы, включая печать |
| `tools/spec_loader.py` | читает `data/spec.json` и, если есть, накладывает на приватные заглушки локальный `private/spec.private.json` |
| `tools/check_fictional_data.py` | телефоны и адреса почты в примерах берутся только из диапазонов, зарезервированных для вымысла |
| `tools/with_lock.sh` | выполняет одновременные запуски `check_examples.sh` по очереди, иначе они затирают извлечённые файлы друг друга |
| `tools/prose_report.py` | помощь редактору: перечисляет предложения с конструкциями противопоставления, риторическими подводками, оценочными формулировками и метафорическими глаголами для проверки |
| `tools/check_drift.py` | детектор устаревания: возраст источников, вакансии, ссылки |
| `tests/` | тесты инструментов; у каждого сторожа есть приманка, на которой он обязан сработать |

## Локальная работа

```sh
./build.sh            # пересобрать книгу после правки parts/
./check_all.sh        # запустить все проверки
python3 tools/check_drift.py   # сверка источников, вакансий и ссылок
```

Просмотр: `python3 -m http.server 8732` и открыть
`http://localhost:8732/fde-advanced.html`.

Соглашения авторов: файлы глав являются фрагментами HTML; локали изоморфны поэлементно
(те же идентификаторы, те же листинги, та же геометрия диаграмм при переведённых
подписях); листинги написаны на самодостаточном Python и исполняются до конца; диаграммы
используют только `currentColor` и семь переменных слоёв; построчные пояснения
ссылаются на строки через `data-anchor` и перенумеровываются
`tools/gloss_lines.py`.

## Деплой

GitHub Pages, деплой workflow-ом `.github/workflows/deploy.yml` на каждый
пуш в `main`. Домен `fde.ragworld.org` привязывается тем же workflow-ом;
на стороне DNS нужна одна запись CNAME `fde → laputski.github.io`.
Принудительный HTTPS включается в Settings → Pages после выпуска сертификата.

## Самообновление

Правило: **данные обновляются автоматически, текст меняется только через редакцию.**

- `ci.yml` проверяет на каждый пуш, что сборка воспроизводима, локали изоморфны,
  диаграммы соблюдают правила, листинги обеих локалей проходят разбор,
  ruff, mypy и исполнение на Python 3.13, 3.14 и предварительном 3.15.
- `weekly.yml` по понедельникам или вручную проверяет, что все источники
  из `data/anchors.json` отвечают, проставляет дату проверки в приложение E
  авто-коммитом и запускает детектор устаревания, который открывает Issue
  с меткой `drift`, если источник старше предельного срока, вакансия снята
  или ссылка умерла; правку текста вносит человек через PR.
- Расписание публичных репозиториев засыпает после 60 дней без коммитов;
  workflow сам оставляет отметку сверки, если тишина длится дольше 45 дней.

*Комментарии в листингах русской локали написаны по-русски намеренно: они часть
русского текста книги. Английская локаль несёт те же листинги с английскими
